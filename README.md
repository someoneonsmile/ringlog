# ringlog

固定大小的单文件环形日志：**管道写入，写满覆盖最旧数据，支持 `-f` 跟随**。

命令行解析、尺寸解析、头部校验、大小显示和换行扫描分别用 `clap`、`parse-size`、
`crc32c`、`humansize`、`memchr` 这几个成熟 crate；环形文件布局、双 slot 头、flock 快照、
行切分与跟随逻辑是本工具的核心，自己实现。产物是单个静态二进制。

```
producer | ringlog -s 64M /var/log/app.ring     # 写入
ringlog -f -n 100 /var/log/app.ring             # 跟随（类似 tail -f）
```

## 解决什么问题

长时间运行的服务日志需要「只保留最近一段，且磁盘占用恒定」。常见做法是 `logrotate`
切文件或定期 `truncate`，前者要多管理文件、后者会丢掉截断瞬间的写入。

ringlog 的做法：**一个文件、大小固定、写满后从文件头覆盖最旧字节**，环形文件层面
真正循环复用，不换 inode、不产生新文件。写入端就是管道，任何程序都能接：

```bash
./server 2>&1 | ringlog -s 128M /var/log/server.ring
```

## 命令行

```
ringlog -s SIZE <FILE>            写入：stdin 管道 → 环形文件（必需一个写者）
ringlog -f [-n N] <FILE>          读取：输出已有数据后持续跟随
ringlog -n N <FILE>               读取：输出最近 N 行后退出
ringlog --info <FILE>             查看文件元信息
```

| 选项 | 说明 |
| --- | --- |
| `-s, --size SIZE` | 文件总大小（含 4 KiB 头区），支持 `64K`、`1G`、`10485760`、`1T`，也支持小数（`1.5G`、`0.5GiB`）；K/M/G/T 为 1024 进制，最小 `8K`、最大 `1T` |
| `-f, --follow` | 跟随：先输出历史，再持续输出新数据；与 `head`/`grep` 等下游配合时遇到 EPIPE 会安静退出 |
| `-n, --lines N` | 最近 N 行；与 `-f` 合用且 `N=0` 时表示跳过历史、只看新数据 |
| `--interval-ms MS` | 跟随轮询间隔，默认 20 |
| `--sync` | 每批记录 `fsync`，更抗断电，吞吐更低（默认不 fsync） |
| `--force` | 目标文件大小/头部不匹配或不是 ringlog 文件时，丢弃旧数据重建 |
| `--info` | 打印文件大小、数据区容量、写位置、累计写入等 |

示例：

```bash
# 采集
./app 2>&1 | ringlog -s 64M app.ring
# 实时跟读（只输出历史最后 100 行，然后跟着新数据）
ringlog -f -n 100 app.ring
# 只看新数据
ringlog -f -n 0 app.ring
# 一次性看最近 200 行
ringlog -n 200 app.ring
# 看元信息
ringlog --info app.ring
# 忘了大小，先查再续写（写入必须给 -s，且要与现有文件一致）
ringlog --info app.ring   # 文件大小 67108864 → 64M
./app 2>&1 | ringlog -s 64M app.ring
```

## 行为细节

### 记录边界

- 输入按 `\n` 切成记录，每条记录以 `\n` 结尾（输入末尾缺换行会自动补一个）。
- 记录不会被环形边界拆断：剩余空间放不下下一条记录时，用**空行填充**到文件尾，
  再从数据区开头继续。所以数据区里永远是一串完整的、以 `\n` 结尾的记录。
- 填充的空行是数据的一部分，会出现在读取输出里（一次环绕最多一行记录长度那么多空行，
  通常只有几个字节）。需要的话用 `grep -v '^$'` 过滤。
- 单条记录最长等于数据区容量（含换行）。超长行截断、**保留行首**，写入进程退出时汇总告警。
- 环形接缝（读取窗口起点）若落在一条记录中间，说明它已被部分覆盖：读取端会整条丢弃它，
  从下一个换行符开始，保证不会输出撕裂的半行；若接缝恰好对齐记录边界，则不会丢任何记录。

### 读取 / 跟随

- 读取端像 `tail -f`：先输出有效数据，再持续输出新增记录。
- 读取端落后超过整个数据区容量时，旧数据已被覆盖，会向 stderr 告警：
  `ringlog: 警告：跟读落后，累计约 N 字节旧数据已被覆盖，跳到最旧数据继续`
  （告警最多每秒一条，避免下游慢时刷屏），
  然后从最旧有效数据继续输出。
- 所有输出都是原始字节，不做 UTF-8 假设，二进制内容原样透传。

### 并发

- **同一文件同一时刻只允许一个写入进程**：写者按目标文件**规范路径**派生 `<FILE>.lock`
  并持 `flock` 独占锁，相对路径、`..`、符号链接都归一到同一把锁；第二个写者会以退出码 2
  失败并提示。锁文件是 0 字节的辅助文件，进程退出/崩溃时锁由内核释放。
- 写者每批记录在文件级 `flock` 排他锁内「先写数据、再更新头部」；
  读者在共享锁内只做「读头部 + 拷贝一个 ≤64 KiB 的数据块」，锁释放后才写 stdout。
  因此读者永远不会看到写了一半的记录，下游管道变慢也不会阻塞写者（写者最多等一次
  64 KiB 的拷贝时间）。

### 崩溃一致性

- 头部用两个 64 字节 slot 交替写入、各带 CRC32C，读取取序号更大的有效 slot。
  写头被撕裂时回退到上一个一致状态，最多丢失最近一批未落盘的数据。
- 默认不 `fsync`：进程崩溃后数据仍在页缓存里，同机可见；**机器断电**可能丢最近数据，
  且头部可能指向尚未落盘的区域，最近一段内容可能是空洞/旧字节（结构仍然自洽）。
  需要更强保证用 `--sync`（每批先落数据再发布头部）。
- 写者被 SIGKILL 后可直接重启续写（同大小、同文件），头部状态自洽。

## 文件格式 v1

```
偏移 0       4 KiB 头区
  +0         slot A（64 字节）
  +64        slot B（64 字节）
偏移 4096    数据区（容量 = 文件大小 - 4096），环形复用
```

slot 布局（小端）：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0..8 | u64 | magic `RINGLOG1` |
| 8..12 | u32 | version = 1 |
| 12..16 | u32 | slot 大小 = 64 |
| 16..24 | u64 | `capacity` 数据区容量 |
| 24..32 | u64 | `write_pos` 下一次写入的数据区偏移 |
| 32..40 | u64 | `total_written` 累计写入字节数（含填充） |
| 40..48 | u64 | `seq` 每次更新 +1，决定 slot 新旧和奇偶 |
| 48..56 | u64 | `epoch` 重置纪元：初始化/`--force` 重建时 +1，读者据此识别重置 |
| 56..60 | u32 | `crc32c(bytes[0..56])` |
| 60..64 | u32 | 保留，0 |

不变量：`total_written % capacity == write_pos`。

记忆口诀：数据区是「长度 capacity 的圆」，`total_written` 是圆上走过的总里程，
有效数据是最近 `min(total_written, capacity)` 字节。

## 限制与取舍

- 只支持单机本地文件系统；网络文件系统（NFS 等）上的 `flock` 语义不可靠，不要用。
- 读取端要在文件已初始化后启动（不像 `tail -F` 会等待文件出现）；写者请先跑起来再接读者。
- 互斥按**文件的规范路径**取锁：相对路径、`..`、符号链接不会绕过锁；但硬链接是同一 inode
  的另一个名字，仍会被当成不同文件，手动删除锁文件也会破坏互斥。
- 单写者。多个写入进程需要外部串行化（例如上游一个 `tee` 进程）。
- 写入进程内存上界约为「数据区容量」（极端情况下一条超长行会缓存到容量上限）；读取进程
  同理会暂存至多半条记录。
- 同尺寸 `--force` 重建时，正在跟随的读者靠 `epoch` 字段检测到重置（即使新的累计写入
  比已读位置大），告警后从重建后的数据继续；改变文件大小时读者会报错退出（数据区几何变了），
  需要重启读者。
- 环形接缝落在记录中间时，最多丢一条最旧记录，这是「绝不输出半行」的代价。
- 写入端：高吞吐时攒满 256 KiB 落一批；低速率输入每 20 ms 兜底落一次盘（`--sync` 为 100 ms），
  跟随端默认每 20 ms 轮询一次，正常情况百毫秒内即可看到新数据。

## 性能（本机 NVMe，release 构建）

- 写入：200 MiB 日志过 64 MiB 环形文件，约 0.07 s（≈2.7 GB/s），文件大小始终 64 MiB。
- 一次 dump 64 MiB（约 63 万行）：约 25 ms（≈2.5 GB/s）。
- 写者每批最多攒 256 KiB，一次锁 + 一次头部更新；低速率输入每 20 ms 兜底落盘。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 正常结束（含下游关闭管道导致的 EPIPE） |
| 1 | I/O 错误 |
| 2 | 用法错误、文件大小/头部无效等数据错误 |

## 代码结构

`ringlog` 库只做引擎，命令行应用在 bin 层：

- `src/format.rs` / `src/ring.rs` / `src/input.rs` / `src/seek.rs` / `src/error.rs`：
  文件格式、环形读写、行分帧、窗口定位、错误分类，**不接触终端**；
- `src/main.rs` + `src/app/`：参数解析（`cli`）、写入泵（`writer`）、跟随输出（`follow`）、
  元信息（`info`）；stdout / stderr 只经过 `app/report`。

```
src/
├── lib.rs format.rs ring.rs input.rs seek.rs error.rs   # 引擎（无终端 I/O）
├── main.rs                                             # 入口：parse → 分派 → 退出码
└── app/  cli.rs writer.rs follow.rs info.rs report.rs   # 应用层
```

分层规则、模块职责与跨模块契约见 [docs/architecture.md](docs/architecture.md)；
这次重构的问题清单与决策见 [docs/architecture-review.md](docs/architecture-review.md)。
